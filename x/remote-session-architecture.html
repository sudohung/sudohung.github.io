远端会话执行生命周期架构优化

从「SSE、Snapshot、Execution、PeerSink 四处判断终态」收敛为「OpencodeClient 只观察、TurnRuntime 统一仲裁、PeerSink 可靠发送」。

01问题与缺陷链

现象是「中断后收不到回复、刷新后对话丢失」，本质是终态判断权不唯一，且恢复信号无法覆盖已删除的执行上下文。

flowchart LR A["用户中断"] --> B["opencode 留下历史 error"] B --> C["Snapshot 未按当前 turn 过滤"] C --> D["15s reconcile 误判 error"] D --> E["删除 execution"] E --> F["终态帧 turnId=legacy / seq=0"] F --> G["接收端 seq 去重丢弃"] E --> H["后续 SSE 真实结果无 execution 可投递"] G --> I["x-b 永久 running"] H --> I

D1 步骤完成误判

assistant tool-step 的 time.completed 被当成整轮完成。

D2 历史 error 污染

Snapshot 中任意旧 error 都会让当前轮永久失败。

D3 双写终态

SSE 与 reconcile 谁先到谁写终态，没有版本或仲裁。

D4 终态序号退化

execution 删除后，PeerSink 无法再取得 turnId/seq。

D5 seq=0 被吞

终态帧 seq=0 被当成重复帧静默丢弃。

D6 迟到结果丢弃

execution 不存在时直接 return，最终真实结果无法补发。

核心结论：不能只修某一个分支。必须同时修正「完成判定、终态仲裁、终态序号、迟到恢复」四个职责。

04领域模型

把长期存在的 opencode session/lease 与短周期的 turn 拆开，避免删除 execution 时丢失终态上下文。

05SSE / Snapshot 仲裁

SSE 正常时 Snapshot 只读；只有 SSE 静默超过 grace period 才允许兜底。终态只能写一次。

sequenceDiagram participant OC as Opencode participant OBS as OpencodeClient participant TR as TurnRuntime participant REC as SnapshotReconciler participant PS as PeerSink OC-->>OBS: SSE chunk / tool / idle OBS->>TR: normalized event TR->>TR: lastSseAt = now TR->>PS: chunk(turnId, seq) alt SSE 仍活跃 REC->>OBS: tick（仅检查，不判终态） OBS-->>REC: snapshot REC->>TR: applySnapshot() TR-->>REC: ignore（lastSseAt 在 grace 内） else SSE 静默超时 REC->>OBS: read current-turn snapshot OBS-->>REC: observation REC->>TR: applySnapshot() alt 当前 turn 明确 idle TR->>PS: done(turnId, seq, text) else 当前 turn 明确 error TR->>PS: error(turnId, seq, reason) else 历史 error / tool-step TR-->>REC: keep running end end
关键约束：Snapshot 只能返回「观察结果」，不能直接返回业务终态；是否结束由 TurnRuntime 根据 SSE 活跃度、当前 turn 范围和 terminal 状态决定。

06终态发送顺序

终态必须先进入可靠发送链路，再释放 lease 和删除运行时上下文。

sequenceDiagram participant TR as TurnRuntime participant PS as PeerSink participant ST as Store participant PL as PeerLink participant EB as ExecutionBinding TR->>TR: state = done TR->>PS: done(turnId, seq, text) PS->>ST: append(peer_outbox, turnId, seq) PS->>PL: send(done) PL-->>PS: ack(turnId, seq) PS->>ST: mark acked TR->>TR: terminalAt = now TR->>ST: update turn = done TR->>EB: release lease TR->>TR: delete runtime binding
禁止：先删除 execution/释放 lease，再通过 execution Map 反查 turnId/seq。终态上下文应由 TurnRuntime 和 PeerSink 持有。

07Turn 状态机

Turn 状态只由 TurnRuntime 修改；每种终态写一次，后续信号只记录，不重复发送。

08Snapshot 判定规则

Snapshot 必须带当前 turn 范围，不能在整个会话历史中 find error。

规则要求
时间范围只接受 createdAt >= turn.startedAt - skew 的消息
error只认当前 turn 的 error；历史 error 返回 historical-error
completion只有 session.idle / execution.succeeded 能判整轮完成
tool-stepassistant.time.completed 仅表示步骤结束
text只拼接当前 turn 的 assistant 消息，禁止使用全部历史 completed
interrupted独立状态，不进入 idle/done 分支
 
SnapshotObservation {
  state: 'running' | 'idle' | 'failed' | 'missing' | 'unknown',
  turnStartedAt,
  messageIds,
  text?,
  failure?: { messageId, createdAt, message },
  reason: 'idle' | 'current-turn-error' | 'historical-error' | 'tool-step' | 'unknown'
}
v1/v2 必须使用同一套归一化规则。当前 v1 的 messages.find(error) 同样需要加当前 turn 过滤。

09seq / ack / 迟到结果

终态 seq

TurnRuntime 独立维护 seq，终态也必须使用真实递增 seq；不能退化为 0。

seq=0 兼容

旧格式 seq=0 视为无序号广播，用 eventId 去重，不能被 seq <= last 静默丢弃。

迟到结果

TurnRuntime 保留到终态 ack 或保留期结束；execution 删除后仍可补发终态。

ack 一致

outbox 使用什么 key，ack 必须回写同一个 turnId + seq，不能混用 promptId/openId。

flowchart LR A["终态事件"] --> B["TurnRuntime seq + 1"] B --> C["PeerSink send(turnId, seq)"] C --> D["peer_outbox"] D --> E["PeerLink send"] E --> F["Peer ack(turnId, seq)"] F --> G["mark acked"] C -->|"ack 超时"| H["保留 terminal / runtime"] H --> I["重连重放"]

10实施顺序

先消除错误与丢失，再引入仲裁和恢复，最后统一可观测性。

P0 正确性

Snapshot 当前 turn 过滤；只认 idle；终态先发送后清理；seq=0 不丢。

P1 仲裁

TurnRuntime；SSE 主事实源；lastSseAt/terminalAt；interrupted 独立映射；文本按 turn 过滤。

P2 恢复

迟到结果补发；inbound turn 落库；profileId 保留；ack key 统一；capability upsert。

验收用例

  • 历史 error + 当前 running：Snapshot 必须返回 running
  • tool step completed 但无 idle：不能产生空 done
  • SSE idle 与 Snapshot error 竞争：SSE 优先
  • 终态释放 execution 后：turnId/seq 仍正确
  • seq=0 legacy 终态：不能被静默丢弃
  • execution 已删除后迟到 SSE：可以补发终态或记录 late result
  • interrupted：不能映射为 done
  • 多轮文本：不能包含上一轮历史正文
一句话：把「会话绑定」「turn 生命周期」「Peer 可靠发送」拆成三个明确边界，终态只由 TurnRuntime 写一次。
