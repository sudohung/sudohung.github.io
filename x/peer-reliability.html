X Peer 连接层与会话可靠性

让任意两个 X 节点（含异构 peer）在互联网上成为可靠对等实例：版本协商、链路 epoch、会话持久化、断线补推、绕过重启、peer 级治理与防环。

01目标与范围

只讨论 X 自身与连接层，不涉及对端 role / 业务语义。

连得上

握手鉴权、能力同步、断线自动重连、优雅下线。

说得清

协议版本与特性协商，异构 peer 可降级。

不丢结果

断网、进程重启后结果可补推，且不重复。

不卡死

每个会话有超时、取消与唯一终态。

可治理

peer 级权限、并发、限流、可观测。

不成环

跨节点调用携带 origin/depth。

非目标：多跳转发、role/业务路由、跨节点 fan-out、动态发现。

02当前实现的问题

骨架已能连通与透传，但缺少可靠性与治理。

类别问题
协议只有 v=1；无特性协商、close/ack；done/error 缺终态细节
连接重连只重建链路；打开中的会话不恢复；旧链路迟到消息无隔离
会话remoteOutbound 仅在内存且无 TTL；peer 掉线不会标记会话
持久化pending_events 已建表但未使用；无 seq 检查点、无重启恢复
安全任何握手成功 peer 可声明任意能力；无 peer 级配额/限流
防环maxHop 配置未生效；1 跳只靠 envelope.to 校验

03设计总览

四个新模块：LinkEpoch、PeerSessionRegistry、PeerOutbox、PeerPolicy。

04协议 v2

信封增加 epoch/origin/depth；hello 增加特性协商；补齐生命周期消息。

4.1 信封扩展

{ "v": 2, "id": "uuid", "type": "chunk", "ts": 1730000000,
  "from": "x-a", "to": "x-b", "traceId": "t-1", "corrId": "s-1",
  "epoch": "link-7f3a", "origin": "x-a", "depth": 0,
  "payload": {} }

4.2 版本与特性协商

{ "nodeId": "x-b",
  "protocol": { "min": 1, "max": 2 },
  "kind": "x",
  "features": ["streaming","close","resume","ack","question","permission"] }
  • 取最高共同版本，features 取交集。
  • 降级：无 ack 不补推；无 resume 重连后标 interrupted；无 streaming 只收最终 done。

4.3 新增消息

消息方向作用
session.close / closed双向关闭会话并释放远端执行态
prompt_ack接收方→发送方确认 prompt 已受理
cancel_ack接收方→发送方cancelled / already-done / unknown
chunk_ack接收方→发送方补推与背压依据
resume / resume.state双向重连后交换会话与 seq 状态
drain / bye双向优雅下线，避免立刻重连

会话字段：openId promptId agentId? done.reason done.usage error.code error.retryable

4.4 会话主流程

sequenceDiagram participant A as X-A 上行 participant B as X-B 远端 A->>B: session.open(openId, context, epoch) B->>B: 幂等检查 + 资源检查 B-->>A: session.accept(remoteSessionId, epoch, features) A->>B: prompt(promptId, text) B-->>A: prompt_ack(promptId) loop 流式 B-->>A: chunk(seq) A-->>B: chunk_ack(seq) end B-->>A: done(seq, reason, usage) A-->>B: chunk_ack(seq)
幂等：接收端持久化 (peerId, kind, key)，重复请求返回首次结果；错误码含 NO_AGENT / RATE_LIMITED / LOOP_DEPTH / BACKPRESSURE / SESSION_EXPIRED。

05连接层

每次握手派生唯一 linkId；重连即新 epoch，旧链路消息被隔离。

5.1 linkId / epoch

linkId = hash(nonceA | nonceB)   // 双方一致，每次重连变化
  • 所有会话消息带 epoch；registry 只接受当前 epoch。
  • 旧链路迟到消息丢弃并计数 stale_epoch_dropped。

5.2 连接状态机

stateDiagram-v2 [*] --> CONNECTING CONNECTING --> CHALLENGE_SENT: hello CHALLENGE_SENT --> AUTH_PENDING: challenge AUTH_PENDING --> ACTIVE: 双向校验 + 特性协商 ACTIVE --> DRAINING: 本端 drain ACTIVE --> CONNECTING: 心跳超时 / 断线（新 epoch） DRAINING --> CLOSED: bye / 超时 AUTH_PENDING --> CLOSED: 校验失败 CLOSED --> [*]

5.3 下线与重连

  • 维护：先 drain，等在途 ack 或 5s，再 bye 关闭；对端不立即重连。
  • 管理台「断开」= drain+bye，保留配置；「删除」= 移除配置。
  • 重连退避 1s→30s + 抖动，增加全局重连预算与连续失败告警。

5.4 握手加固

  • 按 IP 限频（10 次/分钟）、并发握手上限（50）、nonce 一次性 30s。
  • requireWss 非 wss 直接拒绝；指纹不匹配审计。

06会话可靠性

持久化会话 + outbox/ack + resume + 重启恢复，结果不丢不重。

6.1 数据模型

表关键字段
peer_sessionssession_id, peer_id, direction, remote_session_id, epoch, status, last_sent_seq, last_acked_seq, open_id, prompt_id, expires_at
peer_outboxid, peer_id, session_id, seq, type, payload, status, attempts, next_retry_at
peer_inboxpeer_id, kind, key, result, created_at（幂等去重）
peer_auditts, peer_id, session_id, type, code, trace_id, meta

6.2 出站事件与补推

sequenceDiagram participant S as SessionManager participant O as PeerOutbox participant L as PeerLink participant P as 对端 S->>O: append(chunk / done, seq) O->>L: send L->>P: envelope(epoch) P-->>L: chunk_ack(seq) L->>O: mark_acked(seq) Note over O: 断线期间保持 pending L->>P: resume(lastAckedSeq) P-->>L: resume.state(lastSeq) O->>L: replay(seq > lastAckedSeq)

6.3 重连恢复

  1. 链路 ACTIVE（新 epoch），双方发送 resume {sessions:[{sessionId,lastAckedSeq}]}。
  2. 对端返回 status / lastSeq / remoteSessionId / resumable。
  3. 可恢复 → 补推；不可恢复 → interrupted，按策略重开或失败。
  4. 重开使用原 openId/promptId，避免重复执行。

6.4 进程重启恢复

flowchart TB A[启动] --> B[加载 peer_sessions] B --> C{状态 active/waiting?} C -->|否| Z[忽略] C -->|是| D{peer 已连接?} D -->|否| E[标记 interrupted，保留 outbox] D -->|是| F[resume 握手] F --> G{对端可恢复?} G -->|是| H[恢复 active，补推] G -->|否| I{允许重开?} I -->|是| J[用 openId 重开 + 重放 prompt] I -->|否| K[标记 error / expired]

6.5 会话状态机

stateDiagram-v2 [*] --> OPENING OPENING --> ACTIVE: accept OPENING --> ERROR: reject / timeout ACTIVE --> WAITING: question / permission WAITING --> ACTIVE: answer / approve ACTIVE --> CANCELLING: cancel CANCELLING --> CANCELLED: cancel_ack ACTIVE --> DONE: done ACTIVE --> INTERRUPTED: link down INTERRUPTED --> ACTIVE: resume ok INTERRUPTED --> ERROR: resume failed WAITING --> INTERRUPTED: link down DONE --> [*] CANCELLED --> [*] ERROR --> [*]

6.6 超时、租约与幂等

  • open 20s；执行超时按 peer 策略（默认 10min）；idle TTL 10min。
  • 链路关闭立即 abort 入站执行、释放 lease、标记 interrupted。
  • inbound 唯一键 (peer_id, remote_session_id, epoch)；新 epoch 视为新会话。
  • 按时清理 expired 会话与 outbox/inbox 过期记录。

07防环与背压

7.1 防环

  • origin（根节点）+ depth（初始 0）；depth >= 3 或 origin==local && depth>0 拒绝。
  • 远端执行保存 origin/depth；再次发起 peer 调用时递减预算。
  • HTTP 工具可选带 X-Origin / X-Depth，创建 peer 会话时继承。

7.2 背压

flowchart LR A[产生 chunk] --> B{会话队列超过高水位?} B -->|否| C[合并发送 32KB / 50ms] B -->|是| D[暂停读取 / 排队] D --> E{超过硬上限?} E -->|否| C E -->|是| F[关闭会话 BACKPRESSURE]

单帧 1MB；会话 outbox 软上限 8MB、硬上限 32MB；慢消费者连续未 ack 则降级或断开。

08安全与 peer 策略

{
  "id": "x-b", "url": "wss://b/peer", "publicKey": "...", "direction": "both",
  "policy": {
    "canServe": true, "canCall": true,
    "allowedTags": ["java"], "allowedAgentIds": ["oc-1"],
    "maxSessions": 8, "maxConcurrency": 4,
    "sessionTtlMs": 600000,

  }
}
  • capability.update 按白名单过滤；越权条目丢弃并审计。
  • 入站超限返回 session.reject(RATE_LIMITED)。
  • 密钥轮换：双公钥过渡期 + 旧指纹吊销；管理台操作。

09可观测与管理

链路

state、reconnect 次数、RTT、握手失败、stale epoch 丢弃。

会话

按状态计数、outbox 积压、chunk 延迟、错误码分布。

流量

收发字节、限流丢弃、背压触发。

管理

peer 详情、活跃会话、测试连接、drain、拉取能力、密钥轮换。

新增审计表 peer_audit，按 traceId 可查全链路事件。

10兼容与迁移

  • v1 peer：无 epoch/ack/resume/close，走降级路径，UI 标注 degraded。
  • v2 peer：全能力；按 features 交集执行。
  • 迁移：新增 peer_* 表；旧 pending_events 迁移或清空。
  • 灰度：默认关闭 v2，按 peer 开启；稳定后默认 v2。

12里程碑与验收

阶段内容验收
M1协议 v2、epoch、close/ack、peer 掉线、租约释放断线不卡死，取消有确认
M2持久化、outbox、resume、重启恢复、prompt 幂等断网/重启结果不丢不重
M3peer 策略、限流、背压、防环越权/超限/回环被阻断
M4管理台、指标、审计、测试补齐可观测、可运维
最终验收：两节点跨公网运行，任意阶段断网/重启后任务最终一致（不丢、不重、不卡死），旧链路消息被隔离，peer 级策略生效。
