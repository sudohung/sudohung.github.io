00设计演进

一条主线：单节点先跑通，再把跨节点可靠性补齐，最后让节点可描述、可智能选择、可高效传输。

v0.1 骨架

信封协议、挑战应答、AgentPool、基础路由、Web/HTTP、单跳联邦。完成 Web → opencode → 流式回显。

v0.2 可靠连接

链路 epoch、outbox/ack/resume、Peer 策略、防环、断线补推。解决“结果不丢”和治理问题。

v0.3 智能化与性能

xagent.md、peer.describe、PeerDecisionModule、chunk 批量、MessagePack/compact、Worker 持久化、动态 Agent 池、插件。

设计原则：单进程 + SQLite；控制面/执行面分离；会话状态归上行；显式/标签路由优先，LLM 只做远端兜底；X 不托管 opencode。

04握手时序

挑战应答 + RSA-OAEP/AES-GCM 内层身份认证 + 可选 PSK AES-256-GCM 外层门禁 + 公钥指纹固定。

图 4：Peer 建连、PSK 门禁与身份验证

sequenceDiagram participant A as X-A 主动方 participant B as X-B 被连方 A->>B: hello(nodeId, protocols, features, pskId?) B->>A: challenge(nonceA, TTL, features, pskId?) Note over A: 生成 nonceB
RSA-OAEP 包裹 AES-256-GCM key
PSK key = HKDF-SHA256(PSK, nonceA, role, pskId) A->>B: PSK-AEAD auth(inner RSA sealed: nonceB/pubKeyA/nonceA) Note over B: PSK 外层解密/认证失败即拒绝

PSK 不一致则不进入 ACTIVE A->>B: peer.describe(summary, hash, version) B->>A: peer.describe.ack(hash) B->>A: peer.describe(summary, hash, version) A->>B: peer.describe.ack(hash) A->>B: capability.update(profiles) B->>A: capability.update(profiles) Note over A,B: READY，允许 session.open / prompt

05链路状态机

每条 Peer 链路独立状态；重连即新 epoch，旧消息被丢弃。

图 5：PeerLink 生命周期

stateDiagram-v2 [*] --> CONNECTING CONNECTING --> CHALLENGE_SENT: hello CHALLENGE_SENT --> AUTH_PENDING: challenge / auth AUTH_PENDING --> ACTIVE: auth_ok 且双向校验通过 AUTH_PENDING --> CLOSED: 校验失败 / 超时 / 指纹不符 ACTIVE --> DRAINING: 主动下线 / drain ACTIVE --> CONNECTING: 3×心跳超时 / 断线退避 DRAINING --> CLOSED CLOSED --> CONNECTING: 重连
  • 心跳 15s，连续 3 次无 pong 断开；指数退避 1s→30s，带抖动。
  • 同一 Peer 只保留一条 ACTIVE 链路；重复链路被拒绝。
  • 能力协商取双方 features 交集；老 Peer 自动降级。

06会话生命周期

一个会话串行执行多个 turn；审批/提问会进入 waiting，取消/断线进入终态或 interrupted。

图 6：Session 状态机

stateDiagram-v2 [*] --> routing: create session routing --> waiting: 路由需要用户指定 routing --> queued: 已选本地/远端执行者 queued --> running: 获得租约 / 对端 accept running --> waiting: question / permission waiting --> running: answer / approve running --> done: done running --> error: error / timeout running --> cancelled: cancel / cancel_ack running --> interrupted: peer closed / shutdown done --> [*] error --> [*] cancelled --> [*] interrupted --> [*]

串行队列

每会话默认最多 16 个待执行项；队列满返回 QUEUE_TIMEOUT，不杀当前 turn。

上下文预算

默认 32k token；超限保留 system + 最近消息，旧内容折叠摘要。

运行时状态

本地 opencode session 可复用；进程重启后运行中会话标记 interrupted。

上行 X 负责会话与上下文；远端 X 只执行并回传带 seq 的事件；ack 支撑断线补推。

图 8：X-A 将任务转发到 X-B

显式 target → 本地标签 → 远端标签 → 语义选择 → 标签重叠兜底 → 回问用户；每一步可解释。

11批量传输与可靠投递

100ms / 64KB 聚合流式片段；控制事件先 flush；outbox + ack + resume 保证断线后结果可补。

图 12：chunk 批量、ack 与补推

sequenceDiagram participant S as 发送端 SessionManager participant C as ChunkBatcher participant DB as peer_outbox participant L as PeerLink participant R as 接收端 loop 100ms / 64KB / 控制事件 S->>C: append(text / reasoning) C->>C: 合并 segments C->>DB: append chunk.batch(seq) C->>L: send(msgpack / compact / JSON) L->>R: chunk.batch(seq) R-->>L: chunk_ack(seq) L-->>DB: ack watermark end S->>DB: append done(critical) S->>L: send done Note over L,R: 断线 S->>R: resume(lastAckedSeq) R-->>S: resume.state(lastSeq) S->>R: replay pending outbox

批量

默认 100ms/64KB，队列上限 4MB；tool/question/permission/done 前强制 flush。

编码

chunk.batch/chunk_ack 优先 MessagePack，其次 compact，最后 JSON。

可靠

支持 ack 的 Peer 先落 outbox；接收端 seq 去重；done/error 关键事件主连接直写。

兼容

老 Peer 不支持 ack 时走旧路径，不具备断线期间完整补推保证。

12持久化 Worker

把 outbox/ack/inbound/attempt 批量写入 SQLite，避免每个 chunk 都阻塞主线程。

图 13：WorkerPersistence 数据流

flowchart TB E["Session events"] --> M["WorkerPersistence 内存队列"] M -->|"500ms tick / flush"| W["Worker: SQLite"] W --> O[("peer_outbox")] W --> A[("peer_ack_watermark")] W --> I[("peer_inbound_seq")] W --> X["清理 acked / WAL checkpoint"] CR["done / error 关键事件"] --> D["主连接直接写 SQLite"] D --> S["再发送"]
  • 启动时从 SQLite 恢复 pending、ack watermark、inbound seq。
  • 已 ack 行默认保留 1 小时，每 30s 清理，单次最多 5000 条。
  • Worker 崩溃/退出会记录错误；关键终态仍由主连接保证先落盘。

16边界与取舍

保持单机轻量

进程内状态 + SQLite，不引入 Redis/MQ/注册中心；联邦只是把远端 X 当特殊执行者。

可靠优先

outbox/ack/resume 保证结果补推；但旧 Peer 无 ack 时降级。

可解释路由

显式/标签优先，LLM 只做远端多候选；返回候选与原因。

明确不做

多跳、fan-out/聚合、动态 Peer 发现、多租户 RBAC、K8s、托管 opencode。

当前实现边界：Feishu 只有 channel 字段无独立适配器；进程重启不续跑正在执行的 opencode 会话；maxHop 配置保留，1 跳由协议地址约束保证。
