Design Doc · v0.1 · 2026-11-28

X — 跨网络 Agent 协作平台

一个可部署的 Agent 协作节点：对内驱动本机多个 opencode 实例，对外以 Web 与「另一个 X」为接入端；X 与 X 通过长连接组成联邦，实现跨网络的 Agent 协作。

Node.js + TypeScript WebSocket 长连接 挑战应答握手 SQLite 单文件 1 跳联邦

01目标与边界

轻便优先：单进程 + 单文件，不引入额外中间件。

做

接入层、连接层（联邦）、决策层、Agent 池层；会话级跨节点透传。

不做

不管理 opencode 进程生命周期；不依赖 Redis / MQ / 注册中心；MVP 仅 1 跳联邦。

后置

多跳转发、并行 fan-out 与聚合、动态 peer 发现、对外 MCP 接口。

02总体架构

四层职责清晰，联邦只是把远端 X 当成一种特殊执行者。

四条原则：只有 X 暴露公网端口；控制面与数据面分离；单实例可独立工作；会话状态唯一归属上行 X。

03连接层

统一信封 + 挑战应答握手 + 可恢复的连接状态机。

3.1 消息信封

{ "v": 1, "id": "uuid", "type": "prompt", "ts": 1730000000,
  "from": "x-a", "to": "x-b",
  "traceId": "t-...", "corrId": "session-...", "payload": {} }
  • id 全局唯一，用于 at-least-once 去重（每 peer LRU + TTL 10min）。
  • traceId 贯穿跨 X，日志与 Web 调试视图共用。
  • chunk 携带 seq，断线后从最后 seq 续传。

消息类型：hello challenge auth auth_ok capability.update session.open session.accept prompt chunk tool question permission answer done error cancel ping/pong

3.2 握手时序（挑战应答 + 公钥固定）

sequenceDiagram participant A as 主动方 X-A participant B as 被连方 X-B A->>B: hello B->>A: challenge(nonceA, TTL 30s) Note over A: 生成 nonceB A->>B: auth RSA-OAEP(AESKey) + IV + AES-GCM(nonceB, pubKeyA, nonceA) Note over B: 私钥解出 AESKey → 解密
校验 nonceA 一致
校验 pubKeyA 指纹等于配置值 B->>A: auth_ok RSA-OAEP(AESKey2) + IV + AES-GCM(nonceA, nonceB) Note over A: 解密并校验 nonceA + nonceB 一致 A->>B: 进入 ACTIVE，开始通信
两个工程要点：RSA 无法直接加密变长数据，实际用 RSA-OAEP 包裹 AES-GCM 会话密钥；nonceA 必须一次性消费 + 30s TTL + 按 IP 限频，且对端公钥必须与配置指纹比对，防止中间人替换公钥。

3.3 连接状态机

stateDiagram-v2 [*] --> CONNECTING CONNECTING --> CHALLENGE_SENT: 发出 hello CHALLENGE_SENT --> AUTH_PENDING: 收到 challenge AUTH_PENDING --> ACTIVE: 双向校验通过 AUTH_PENDING --> CLOSED: 校验失败 / 超时 / 指纹不符 ACTIVE --> DRAINING: 主动下线 ACTIVE --> CONNECTING: 心跳超时 3×15s 或断线退避 DRAINING --> CLOSED

3.4 断线与幂等

  • 心跳 15s，连续 3 次无 pong 判定断线；重连指数退避 1s → 30s（带抖动）。
  • 远端执行不因连接断开而中断，结果落库；重连后按 corrId + seq 补推。
  • 去重保证至少一次，会话内消息按 seq 保序。

04决策层

能力注册表为主，LLM 只做兜底；选择过程可解释。

{ "agentId": "oc-1", "instanceId": "i-1", "tags": ["code-review", "java"],
  "model": "xxx", "maxConcurrency": 2, "status": "healthy",
  "source": "local", "peerId": null, "version": 12 }
flowchart LR S[消息] --> E{显式 target?} E -->|是| P1[直发指定 agent/peer] E -->|否| L{本地精确 tag?} L -->|是| P2[本地最小负载] L -->|否| R{远端精确 tag?} R -->|是| P3[远端 X 执行] R -->|否| LLM[LLM 在候选清单中选择] LLM --> U[仍不确定则回问用户]
  • 不舍近求远：本地有匹配就不再打到远端。
  • 能力来源：静态配置 + 建连上报 + 变更增量推送，带 TTL（借鉴 Nacos 注册与健康模型）。
  • 上下文预算：默认 32k token 估算；session.open 超限先在上行做摘要，之后只发增量 delta；远端会话空闲 TTL 10min，由上行回收。

05Agent 池层

agent = 独立 opencode 实例，X 只连接不托管。

{ "instances": [
  { "id": "oc-1", "baseUrl": "http://opencode-1:4097", "token": "***",
    "workdir": "/workspace/a", "tags": ["java"], "model": "default",
    "maxConcurrency": 2 }
]}

健康与熔断

15s 探测；连续 3 次失败熔断 30s（Dubbo 风格）。

并发控制

全局信号量 + 单实例信号量 + 单会话串行锁。

会话粘性

sessionId 哈希固定实例；故障时在上行重开并做有界上下文重放。

交互事件

question / permission 透传给会话所有者，未响应默认拒绝。

06接入层

Web 与机器客户端共用一套 API，鉴权与 peer 通道隔离。

接口说明
WS /wsWeb 实时通道：消息流、事件、审批
HTTP /api/sessions会话列表与详情
HTTP /api/messages发送消息
HTTP /api/capabilities能力 / agent / peer 状态
HTTP /api/approvals审批响应
  • Web：Vite + React 轻量单页，无重型组件库；含会话列表、流式消息、路由解释卡片、审批横幅、状态面板。
  • 鉴权：Web 用户走统一 Bearer/Cookie Token；peer 走独立握手通道，不复用 Web Token。

08部署与目录

单镜像 + Docker Compose；只有 X 暴露公网端口。

x/
  src/protocol/     信封、消息类型、编解码
  src/connection/   握手、PeerLink、状态机、重连、去重
  src/decision/     能力注册表、路由、上下文预算
  src/pool/         OpencodeClient、健康、信号量、粘性
  src/access/       HTTP/WS API
  web/              轻量前端
  config/           peers.json、agents.json、keys/
  data/             x.db
  • Compose：x 暴露唯一公网端口；opencode-1..N 仅内网，各自挂载独立 workspace 卷。
  • CLI：x keygen 生成密钥对；x peer add 写入对端地址与公钥指纹。

09关键取舍

取舍原因
进程内状态 + SQLite，不引中间件单节点轻便，部署即用；借鉴 Redis/Nacos 模式而非依赖组件
静态 peer + 1 跳转发避免环与风暴，MVP 够用，多跳后置
显式/标签路由优先，LLM 只兜底可解释、可控制、成本低
会话状态归上行，远端只持执行态收尾与续写责任唯一，避免双写冲突

10里程碑与验收

  1. 骨架：协议 + 握手 + 单 agent 打通（Web → 本地 opencode → 流式回显）。
  2. 池与决策：多实例、健康熔断、标签路由、审批透传。
  3. 联邦：X 间建连、能力上报、会话级透传、断线续传。
  4. 加固：指标与日志、消息重放、审计视图。
验收标准：两个 X 实例部署在不同网络，A 侧 Web 发一条任务，经决策选择 B 侧 agent 执行，B 侧流式回传，A 侧展示并可中途取消；断网 30s 内重连后结果不丢。

链路隔离

每次握手派生唯一 linkId（epoch）；重连即新 epoch，旧链路迟到消息丢弃。

结果不丢

chunk/done 先写 PeerOutbox；对端 ack 后清理；重连按 lastAckedSeq 补推。

重启恢复

持久化 sessionId ↔ remoteSessionId / caller 凭证 / taskId；启动后 resume 或按策略重开。

可治理

peer 级白名单、并发、速率、TTL、requireWss；能力声明按策略过滤。

可观测

链路状态、重连次数、outbox 积压、会话状态、chunk 延迟、错误码。

防环

session.open/prompt 携带 origin + depth；超深或同源回环直接拒绝。

完整状态机、补推时序、进程重启恢复、peer 策略与测试计划见 《Peer 连接层与会话可靠性设计 v0.2》。
